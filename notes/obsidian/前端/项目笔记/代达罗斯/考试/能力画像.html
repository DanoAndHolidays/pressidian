下一次出题优先级

  1. 用完整 Issue 复测 queryKey 工厂、查询与失效一致性，以及 mutation 成功后的可观察刷新。
  2. 用可点击卡片内含按钮/链接的真实 Bug，要求同时恢复父级主行为和子级事件隔离，并补交互测试。
  3. 要求从 tRPC/共享 Schema/IDE 类型提示确认 payload 与输出类型，禁止用双重断言掩盖不兼容。
  4. 在真实任务的验收标准中加入失败反馈，要求 mutation error 能被用户感知。
  5. 提交前运行 typecheck、目标 lint 与 git diff --check，清理 TODO、注释代码、尾随空格和范围外 UI 回退。

学习偏好与后续出题约束

  • 默认改用真实开发任务制：提供 Issue、可观察现象、验收标准和修改边界，保留完整源码，不再预先指定所有目标文件。
  • 考生先提交代码探索结果、影响范围、方案与验证计划，再自主实现、运行检查并提交交付说明。
  • 评分以验收行为、代码库探索、边界处理、测试验证和方案取舍为主，不以还原 Git 标准答案为目标。
  • 填空题只用于同一基础错误重复出现后的短期专项复测，建议不超过单场训练的 20%。
  • 允许使用 IDE、类型跳转、仓库搜索和现有测试；要求说明证据来源，区分独立实现与直接恢复答案。
  • UI 任务继续不考生僻 className 和翻译 key，但必须考察状态反馈、事件边界、受控数据和可访问语义。
