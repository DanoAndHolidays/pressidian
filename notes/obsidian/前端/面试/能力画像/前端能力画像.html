> 目标：React + TypeScript 前端开发（校招）；主栈：React, TypeScript；公司档位：互联网中大厂。 > 分数只描述已有证据。— 表示尚未形成足够的独立验证，不等于能力为零。

当前结论

知识库显示出较广的前端学习覆盖，React、JavaScript、TypeScript、浏览器事件与项目实践材料尤其密集。真实考试已经证明你能完成多类 React 状态流、表单和异步 UI 任务，但稳定性仍受缓存一致性、完整交互链、错误反馈、测试验证和提交前清理影响。现有证据主要来自实现与阅卷，独立答辩和现场接管证据不足，因此 React 应用能力可判断为发展中，其他大部分基础方向暂不做乐观定级。

分维度说明

HTML 与语义化

优势或已有基础：

  • 目录中存在 HTML、表单和语义相关学习材料。

缺口或证据不足：

  • 缺少语义化表单、可访问名称和真实页面实现的独立证据。

下一步：在后续 React UI 任务中加入语义标签、键盘访问和表单行为验收。

CSS 与布局

优势或已有基础：

  • CSS、Flex、Grid 和样式方向覆盖较广。

缺口或证据不足：

  • 现有考试曾出现布局信息缺失和范围外 UI 回退，尚不能证明独立还原与响应式能力。

下一步：下一周期安排一个响应式列表或详情页实现，并用截图和键盘检查形成证据。

JavaScript

优势或已有基础：

  • 数据类型、转换、异步与现代 JavaScript 的笔记覆盖较完整。
  • 不可变数组和 Set 更新在真实题目中出现过正确实现。

缺口或证据不足：

  • 缺少覆盖作用域、原型、事件循环、Promise 并发与错误边界的统一独立验证。
  • 面经中的原回答与参考答案尚未分离。

下一步：完成一次 Promise 并发控制代码题并进行事件循环因果推演答辩。

TypeScript

优势或已有基础：

  • 类型体操、泛型防抖和类型工具有较多学习与局部实践。

缺口或证据不足：

  • 真实任务中曾使用双重断言掩盖接口关系。
  • 类型体操覆盖不能替代领域对象、接口输出和表单边界建模。

下一步：在当前异步一致性考试中从真实接口类型确认 payload，并禁止无理由双重断言。

浏览器与 DOM

优势或已有基础：

  • 能处理 DOM 主题副作用和按钮 stopPropagation。
  • 已针对 closest 与 stopPropagation 做过深入复盘。

缺口或证据不足：

  • SSR 全局 API 边界和可选链位置仍有错误记录。
  • 父容器主行为与子级事件隔离曾只完成一半。

下一步：用可点击卡片内含按钮/链接的真实 Bug 独立复测完整事件链。

网络与安全

优势或已有基础：

  • 网络、请求、协议、缓存和认证相关目录覆盖较广。

缺口或证据不足：

  • 扫描关键词与 React 请求笔记有重叠，140 篇命中不能视为网络掌握。
  • 缺少 HTTP 缓存、跨域、认证和安全问题的独立推演。

下一步：当前周期结束后安排一次 HTTP 缓存与跨域场景化问答。

React 核心

优势或已有基础：

  • Hooks 依赖、Context、表单 reset 时序和异步三态多次取得较好结果。
  • 能够在真实组件中完成常见状态与副作用处理。

缺口或证据不足：

  • 缺少系统的独立答辩和现场变化题证据。
  • Fiber 等原理笔记尚未通过因果推演验证。

下一步：完成当前考试后进入独立答辩，解释状态源、Effect 生命周期和过期结果隔离。

React 应用生态

优势或已有基础：

  • React Hook Form、Zod、Refine CRUD、路由和 mutation 有真实实践。
  • 表单 reset、提交守卫和部分数据流已达到较高正确率。

缺口或证据不足：

  • React Query 查询 key 与失效 key 曾不一致。
  • 接口类型确认、错误 UI 和缓存生命周期尚未稳定。

下一步：独立实现 queryKey 工厂、成功失效和失败反馈，并用测试或 Devtools 证明刷新。

前端工程化

优势或已有基础：

  • 具有构建、类型检查、包管理和性能优化的知识目录。
  • 能使用 typecheck、lint 和 git diff 检查结果理解问题。

缺口或证据不足：

  • 多次交付仍残留 TODO、尾随空格、注释代码和未使用变量。
  • 缺少完整独立执行并解释构建链和 CI 结果的证据。

下一步：把 typecheck、目标 lint、相关测试和 git diff --check 固化为每次交付清单。

测试与质量

优势或已有基础：

  • 已整理测试分类、测试金字塔及 Jest/Vitest 基础。

缺口或证据不足：

  • 真实任务缺少相关前端回归测试。
  • 调试和占位内容清理问题重复出现。

下一步：当前考试必须补两条异步竞态回归测试，并完成全部提交前检查。

性能与可访问性

优势或已有基础：

  • 了解 Core Web Vitals，真实组件中使用过 alert、Label 和文字按钮。

缺口或证据不足：

  • 分页禁用、option key 和完整交互语义仍有缺口。
  • 没有真实性能测量和优化前后对比证据。

下一步：在下一次 UI 任务中加入键盘、状态反馈和性能测量的最小验收。

编码与算法

优势或已有基础：

  • 仓库存在代码题、手写题和面经积累。

缺口或证据不足：

  • 缺少计时、独立完成、复杂度分析和边界测试记录。

下一步：完成一题 Promise 并发控制和一题常见数据结构题，记录时间、测试和复盘。

项目设计与交付

优势或已有基础：

  • 已完成多场跨 Hook、组件和页面的真实前端任务。
  • 能处理表单、mutation、异步 UI 和路由等完整功能片段。

缺口或证据不足：

  • 完整调用链检查不稳定，曾出现父行为断开、错误路由和缓存地址漂移。
  • 交付清理、测试证据和独立接管尚未形成稳定闭环。

下一步：完成 EXAM-20260730-02 的实现、测试、交付说明、独立答辩和现场接管。

面试表达

缺口或证据不足：
